金泰工作流 · 全流程详解

原著 → 剧本 → 分镜 → 资产设定 → 生成包整理 | 从文学原著到「视频生成就绪包」的标准化前期生产系统 · 全程由执行助手推进,六道人工门验收 · v1.1 修订稿
一句话定义:金泰工作流不是"把剧本变成提示词",而是把原著逐层转换为一套可追溯、可锁定、可批量执行、可检查、可返工的前期生产包。终点不是成片,而是一个镜头清单完整、资产引用有效、关键帧已批准、逐镜提示词已生成、命名统一、质检通过的视频生成就绪包。
核心顺序不可倒置:导演与叙事决定 → 工种深化 → 资产锁定 → 镜头数据化 → 批量生成准备。不能先堆提示词,再反过来猜故事和人物。
运转方式:十个阶段的文档生产、拆解、编号、编译、检查全部由执行助手自动完成;人只把守六道门——事实边界、剧本、导演阐述、资产母版、镜头意图、就绪包交付。凡属主题、表演、审美、节奏的规则,自动起草后必须经人批准才能成为下游依据。机器做多人做对

02三个不能混用的母版

整个工作流围绕三份母版协同运转,任何一份改动都要触发下游影响检查。
母版回答的问题包含内容
内容母版讲什么原著事实库、改编圣经、当前锁定剧本、场景清单与人物弧、伦理/版权/历史红线。剧本改动必须触发分镜与资产影响检查,不能只改一份文档。
视觉资产母版谁、在哪、穿什么、拿什么人物(多角度、体态、标志物)、场景(空间结构、出入口、表演区、光源)、服装(阶段造型、污损状态)、道具(尺寸、材质、持有者)。每项写清固定项、可变项、禁止漂移项、参考图、批准版本。
镜头数据母版怎么拍、怎么动、怎么听逐镜结构化字段(见 P6);文档版供人审,数据版(CSV/JSON)供校验与批处理,两者出自同一数据源,不得分别手改。

03阶段详解:前期十阶段 + 下游延伸段

P0–P9 为前期十阶段;文末虚线卡 P10–P11 为下游延伸段。每阶段标注:自动执行的动作、必须产出、通过标准、人工门(如有)、失败退回。

P0项目立项 人定边界·自动建档

自动执行:建立项目目录骨架与编号规则;固定三字段——project_code(文件短码)/ display_title(对外片名)/ source_title(原著名),防止项目名漂移;生成项目简报与风险表模板。
人来决定:版权状态、目标受众、画幅、单集片长、集数、风格边界、产能上限。
产出:项目简报、风险表、目录骨架。
通过标准:所有硬约束有明确答案;未知项标成"待确认",不允许含糊带过。

P1原著解析 自动提取

自动执行:通读原著,提取事实、人物、时间线、地点、物件、因果链;每条事实编号 SRC-001 并回指原文页码/段落与可信度;事实与推断分栏,严格分开。
产出:原著索引、事实卡、人物关系图、时间线、禁改清单。
通过标准:关键情节都能回指原文;事实与推断不混写。
G1 原著门(人工):确认事实、版权、伦理边界和改编自由度。这道门定下"哪些绝不能动",后续所有阶段(含下游延伸段)都受它约束。

P2改编设计 自动起草·人定方向

自动执行:依据 G1 结论起草改编圣经——类型、叙事视角、主题、季集结构、人物弧、删改合并方案;每一处删改附叙事理由并核对不破坏因果与动机。
产出:改编圣经、季纲、分集表、人物弧表。
通过标准:每次删改都有叙事理由;因果与人物动机完整。
人定方向的落盘:类型、视角、主题、删改原则等方向性决策列成清单,在 G2 剧本门与剧本一并批准,批准记录存 00_project/。
失败退回:与禁改清单冲突 → 回 P1 复核事实。

P3剧本开发 自动成稿

自动执行:分集梗概 → 节拍表 → 完整剧本三级推进;逐场核对六问(观众已知什么/谁想要什么/阻力/转折/离场新知/下一场为何必然);生成场景清单,片长可计算。
产出:分集梗概、节拍表、完整剧本、场景清单。
通过标准:每场有目标、阻力、转折、离场状态;答不出六问的场先改剧本,不靠镜头美化掩盖。
G2 剧本门(人工):确认故事清楚、人物成立、节奏与片长可控。通过后剧本进入锁定版,再改动走版本变更并评估下游影响。

P4导演设计 自动起草·人批阐述

自动执行:起草表演原则、调度、摄影、美术、灯光、剪辑与声音逻辑,写成可检查的规则(而非形容词堆积);起草连续性规则。
产出:导演阐述、视觉圣经、声音圣经、连续性规则。
通过标准:所有风格选择都有叙事动机;意象只承担结构/情绪/主题功能,不替代事实交代。
失败退回:风格选择缺叙事动机 → 本阶段重写;与剧本冲突 → 回 P3。
G3 导演门(人工):表演、审美、节奏属于必须由人判断的范畴——导演阐述与视觉/声音圣经经人批准后才并入内容母版,成为 P5–P8 的上游依据;批准记录存 00_project/。

P5资产设定 自动建卡·人批母版

自动执行:从剧本与导演设计中抽取全部人物/场景/服装/道具,建立资产登记表与设定卡;每个资产唯一编号(CH004 / LOC012 / CH004-CO02 / PR008);逐项写固定项、可变项、禁止漂移项;组织参考图进入 working → review 流转。
关键规则:角色先行,剧情后行——先批角色母版,再生产复杂剧情图;换装只改状态不新建人物;昼夜是场景状态不新建地点;角色靠骨相、体态、劳动痕迹、专属物件区分,不靠脸谱。
产出:资产登记表、设定卡、参考图、禁用项、母版锁。
通过标准:每个核心资产有唯一编号、批准图和可变/不可变项。
G4 资产门(人工):确认"这就是这个角色、这个世界",随后锁定母版。母版一经批准不覆盖,任何变化产生新版本;验收只读 approved/。

P6分镜工程 自动拆解

自动执行:先拆场再拆镜;每个镜头必须归属至少一种叙事功能(建立空间/人物关系/动作/反应/物证/转场/留白/声音先行),无功能镜头删除或合并;逐镜填齐最低字段并编译为镜头数据库。
逐镜最低字段:时长、景别、机位、运动;角色/服装/场景/道具引用;走位与动作起止;光源动机;台词与三类声音;前后连续性;首帧静态;动态变化;禁止发生的错误。静帧描述与动态描述分开写。
产出:镜头表、一镜一页、场镜头覆盖表、声音表。
通过标准:时间线无空洞无重叠;每句台词和关键动作有画面归属。

P7关键帧 自动生产·人审意图

自动执行:按分镜逐镜生产首帧、必要尾帧、Hero 镜头与环境空镜;全部采用稳定引用 @CH004 + @LOC012 + @CH004-CO02 + @PR008(双引用镜头:人物+场景同时引用,防"人对景错/景对人漂");生成总览图与验收表。
产出:关键帧、总览图、关键帧验收表。
通过标准:身份、年代、空间、轴线、光线、构图逐项通过。
失败退回:构图/信息不清 → 回 P6 重拆;人物漂移 → 回 P5 修母版。
G5 关键帧门(人工):确认每个镜头的叙事意图可被一眼读懂。批准后关键帧移入 07_keyframes/approved/,同时镜头表 approval_status 置为已批准——目录与字段必须一致,机检两边核对。

P8生成包整理 全自动编译

自动执行:把已锁定信息编译为逐镜可执行任务:首帧提示词表 + 动态提示词表 + 引用清单 + 批次任务清单(JOB-EP01-0001)+ 版本表;按时长、优先级、批次排队;每个任务记录输入引用、输出路径、版本与状态。
硬规则:每个任务只引用 approved/ 内的已批准母版;提示词内不粘贴整段人物描述,只用稳定引用。
产出:动态提示词、引用清单、任务清单、批次表、版本表。
通过标准:引用有效率 100%;输入输出路径明确。

P9就绪包质检 自动查缺·人工抽审

自动包检(执行助手,只针对就绪包内对象):
  • 文件:缺失、打不开、重复、命名错误、版本错位
  • 数据:ID 重复、引用不存在、字段空缺、时间线空洞/重叠
  • 图像(关键帧/参考图):尺寸、画幅、过暗、近似重复、结构异常
  • 连续性:人/服/道/景状态与镜头表一致
  • 覆盖:镜头/引用/已批准关键帧三项覆盖率(关键帧只认 07_keyframes/approved/ 且与 approval_status 字段一致)
  • 交付:任务清单、输入文件、输出位置、批准状态齐全
人工抽审:抽查逐镜提示词与关键帧是否仍忠于镜头意图、有无绕过门批准的临时改动。

包级红线(0 容忍):缺项、引用失效、未批准母版被引用、命名/版本错位、门批准记录缺失。

视频层面的技术检查(黑屏/冻结/帧率)与 10 分制审片属于下游延伸段 P11 片质检,见总流程图下方说明。
G6 交付门(人工):确认就绪包完整、可批量执行,没有隐藏的临时决定。自动检查不能替代人工判断。

P10–P11下游延伸段:生成执行与片质检 自动跑批·人工审片

P10 生成执行(自动):按批次表消化 JOB 任务清单,逐任务记录输入引用、输出、版本与结果;失败任务进入重试队列。
P11 片质检:自动——实际时长、黑屏、纯噪点、冻结、编码、帧率;人工——10 分制逐镜审片(叙事清晰度、身份一致性、表演自然度、构图可读性、时代可信度、前后连续性、声画关系、是否值得进剪辑)。
片级红线(一票否决,不以平均分抵消):人物换脸、时代穿帮、关键物证错误、动作因果颠倒、伦理越界、引用失效。
返工:按下方归因表返回对应前期层级;技术坏片保持输入不变只重跑原任务。

06返工归因表

主要服务于下游延伸段 P11 片质检,前期各门退回同样适用;发现问题先判层级再动手,技术坏片保持输入不变只重跑原任务。剧本或母版层的修正必须同时产出变更影响单(受影响的分镜/关键帧/任务清单),存 00_project/。
问题类型返回层级处理方式
事实或人物动机错误原著 / 剧本 (P1–P3)修正内容母版并检查下游影响
人物或世界观漂移资产母版 (P5)修正引用、固定项或批准图
构图、动作或信息不清分镜 (P6)重拆镜头、走位或画面重点
执行结果偏离镜头意图生成包 (P8)调整动态描述、引用或参数
黑屏、冻结、损坏原任务输入不变,技术重跑;不能用重跑掩盖上游问题

08落地路线与最简版

三轮推进:
  • 第一轮·黄金样板:选体量小、事实链清晰的完整短片,按新目录与版本规则重新编目,验证全链追溯。
  • 第二轮·规模压测:用系列项目验证多角色母版、服装状态、考据红线、多集批量任务管理。
  • 第三轮·从零运行:全新短片只用本规范,全程记录每道门的批准时间、退回原因与返工次数,据此定 v1.2。
最简版(1–3 分钟、角色少、无复杂考据):
